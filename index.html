Projection : choisir les champs

SyntaxeEffet

Tri, skip, limit

db.Films.find().sort({ note: -1 })        // -1 = décroissant
db.Films.find().sort({ annee: 1, note: -1 })  // multi-critères

Ordre d'application TOUJOURS : sort → skip → limit, quel que soit l'ordre d'écriture.

// $set
db.produits.updateOne(

  { $set: { prix: 350 } }

db.joueurs.updateMany(
  { club: "PSG" },
  { $inc: { "performance.minutes_jouees": 100 } }

  { club: "Al-Hilal" },
  { $unset: { "performance.minutes_jouees": "" } }
)

)

// $pull — retirer tous les éléments correspondants
db.joueurs.updateOne(
  { nom: "Mbappé" },
  { $pull: { matchs: { adversaire: "Lens" } } }
)

Modifier un tableau : $ / $[elem] / arrayFilters

OutilPortée
$ (positionnel)1ʳᵉ occurrence correspondante
$[elem] + arrayFiltersToutes les occurrences qui respectent la condition
$[] (all positional)Toutes les occurrences (sans filtre)
// $ : seulement la première
db.joueurs.updateOne(
  { nom: "Hakimi", "matchs.adversaire": "Marseille" },
  { $set: { "matchs.$.note": 9.0 } }
)

// $[elem] + arrayFilters : toutes les correspondances
db.joueurs.updateOne(
  { nom: "Hakimi" },
  { $set: { "matchs.$[m].note": 9.0 } },
  { arrayFilters: [ { "m.adversaire": "Marseille" } ] }
)

// $inc sur toutes les occurrences avec bonus >= 1
db.etudiants.updateMany(
  {},
  { $inc: { "examens.$[e].note": 0.5 } },
  { arrayFilters: [ { "e.bonus": { $gte: 1 } } ] }
)

Projection : opérateurs de tableau

OpérateurRôle
$filterGarder les éléments qui respectent cond
$mapTransformer chaque élément
$reduceRéduire le tableau à une valeur (somme, concat…)
$arrayElemAtÉlément à un index
$sliceN premiers éléments
$sizeTaille
$concatArraysConcaténer deux tableaux

Version minimale : MongoDB 4.4+. Avant, il faut passer par aggregate() + $project.

// $filter + $map : extraire un champ des éléments filtrés
db.joueurs.find({}, { _id: 0, nom: 1,
  adversaires_note_8: { $map: {
    input: { $filter: { input: "$matchs", as: "m",
      cond: { $gte: ["$$m.note", 8] } } },
    as: "x", in: "$$x.adversaire" } } })

// $filter + $arrayElemAt : premier élément filtré
db.joueurs.find({}, { _id: 0, nom: 1,
  premier: { $arrayElemAt: [
    { $filter: { input: "$matchs", as: "m",
      cond: { $gte: ["$$m.note", 8] } } }, 0 ] } })

Notation : $$m = variable d'alias (as), $matchs = champ.

Pipeline d'agrégation

db.commandes.aggregate([
  { $match:   { statut: "payée" } },          // filtre
  { $group:   { _id: "$client", total: { $sum: "$montant" } } },  // regroupe
  { $sort:    { total: -1 } },                // tri
  { $limit:   10 },                            // top 10
  { $project: { _id: 0, client: "$_id", total: 1 } }  // projection
])
ÉtapeRôle
$matchFiltrer (comme find)
$groupRegrouper + calculer ($sum, $avg, $min, $max, $push…)
$projectChoisir / transformer les champs
$sort / $skip / $limitTri, pagination
$lookupJointure avec une autre collection
$unwindDéplier un tableau en documents
$countCompter

$lookup (jointure)

db.commandes.aggregate([
  { $lookup: {
    from: "clients",            // collection à joindre
    localField: "client_id",    // champ local
    foreignField: "_id",        // champ étranger
    as: "client"                // nom du tableau résultat
  }}
])

Embedding ou referencing ?

Embedding = lecture optimisée. Referencing = écriture optimisée.

EmbeddingReferencing
AvantagesLecture rapide, cohérence, pas de jointurePas de duplication, mises à jour simples
InconvénientsDoc plus gros (16 Mo max), duplication, MAJ lourdesPlusieurs requêtes ou $lookup
QuandUn-à-peu, données lues ensembleUn-à-plusieurs, plusieurs-à-plusieurs

Trois niveaux d'embedding

  • Simple : petit sous-document imbriqué directement.
  • Intermédiaire : tableau de sous-documents (un-à-plusieurs).
  • Avancé : documents profondément imbriqués → opérateurs $filter, $map, $reduce, $size, $slice, $arrayElemAt.

Index

// Créer un index (accélère les requêtes)
db.users.createIndex({ email: 1 })       // croissant
db.users.createIndex({ nom: 1, age: -1 }) // composé
db.users.createIndex({ email: 1 }, { unique: true })
db.users.createIndex({ contenu: "text" }) // full-text

// Voir / supprimer
db.users.getIndexes()
db.users.dropIndex({ email: 1 })

Règle : un index rend les lectures plus rapides mais les écritures plus lentes (il faut maintenir l'index). À créer sur les champs souvent filtrés / triés.

Pièges classiques

  • Sous-document : toujours la notation pointée "adresse.ville".
  • Deux conditions sur le même élément : $elemMatch (sinon deux éléments différents peuvent satisfaire chacun une condition).
  • $all : sur le champ de l'élément ("examens.matiere"), pas sur le tableau entier.
  • $pull : retire TOUS les éléments correspondants.
  • replaceOne : aucun opérateur, tous les champs à garder réécrits, _id conservé.
  • Ordre d'application : sort → skip → limit, toujours.
  • Projection : $filter, $map, $slice, $arrayElemAt dans find() demandent MongoDB 4.4+.
  • $arrayElemAt sur tableau vide : champ absent du résultat (pas une erreur).
  • Flottants : 9.1 + 0.2 peut s'afficher 9.299999999999999. C'est normal.
  • Index : ne pas abuser — chaque index ralentit les écritures.

Conditions

elseif ($note >= 14)  { $m = "Bien"; }
elseif ($note >= 12)  { $m = "Assez bien"; }

switch

switch ($jour) {
  case 1: $nom = "Lundi"; break;   // break obligatoire !
  case 2: $nom = "Mardi"; break;
  case 6:
  case 7: $nom = "Week-end"; break; // cases regroupés
  default: $nom = "Autre jour";
}

switch utilise une comparaison souple (==).

match (PHP 8+)

$nom = match ($jour) {
  1 => "Lundi",
  2 => "Mardi",
  6, 7 => "Week-end",
  default => "Autre jour",
};

// Tester des intervalles
$mention = match (true) {
  $note >= 16 => "Très bien",
  $note >= 14 => "Bien",
  default     => "Non validé",
};

match est une expression (renvoie une valeur), utilise ===, pas de break. Erreur UnhandledMatchError si aucun cas ne correspond et qu'il n'y a pas de default.

POO (Programmation Orientée Objet)

class Etudiant {
  // Propriétés
  public string $nom;
  private int $age;
  protected string $ville;

  // Constructeur
  public function __construct($nom, $age, $ville) {
    $this->nom = $nom;
    $this->age = $age;
    $this->ville = $ville;
  }

  // Méthode publique
  public function getAge(): int {
    return $this->age;
  }

  // Méthode protégée (héritage uniquement)
  protected function description(): string {
    return "$this->nom ($this->age ans)";
  }
}

// Instanciation
$e = new Etudiant("Amal", 25, "Agadir");
echo $e->getAge();

Sécurité (bonnes pratiques)

  • Ne jamais faire confiance aux entrées utilisateur ($_GET, $_POST).
  • Échapper les sorties HTML avec htmlspecialchars() pour éviter les XSS : echo htmlspecialchars($nom);
  • Requêtes préparées avec PDO pour les injections SQL : $stmt = $pdo->prepare("SELECT * FROM users WHERE email = ?");
  • Mots de passe : utiliser password_hash() et password_verify().
  • CSRF : ajouter un token dans les formulaires.

Pièges classiques

  • Comparaison : == est piégeux ("1e3" == "1000" → true). Toujours privilégier ===.
  • Chaîne vide vs "0" : empty("0") renvoie vrai, ce qui surprend souvent.
  • Concaténation : ne pas utiliser + pour les chaînes (utiliser .).
  • Tableaux : array_merge() réindexe les clés numériques, + ne les réindexe pas (garde les valeurs à gauche).
  • Variable non définie : en PHP 8, c'est un Warning. Toujours utiliser isset() ou ??.
  • Modification dans une boucle foreach : foreach ($tab as $val) travaille sur une copie. Pour modifier, utiliser foreach ($tab as &$val) puis unset($val) après la boucle.
  • Sessions : session_start() doit être appelé avant tout envoi de contenu HTML.

Fondamentaux de la qualité

Définition : Le degré auquel un produit logiciel satisfait les besoins explicites et implicites des parties prenantes dans des conditions spécifiées.

2 piliers :

  • Produit : fiabilité, sécurité, maintenabilité…
  • Processus : méthodes, outils, rigueur du développement.

Modèle de qualité : relier attributs mesurables et qualité perçue : Qualité ≈ f(attributs).

Les 4 niveaux de besoins

NiveauDéfinition
ExprimésCe que le client a formulé
SpécifiésFormalisés dans le cahier des charges
RéalisésEffectivement implémentés
Vrais besoinsAttentes réelles, souvent non exprimées

Chaîne causale

Erreur (humaine) → Défaut (dans le code/conception) → Défaillance (observable en exécution).

Exemple : oubli d'un cas → division par zéro non gérée → crash de l'application.

Modèle SQuaRE (ISO/IEC 25010)

Fournit un cadre pour évaluer la qualité via 8 caractéristiques mesurables :

CaractéristiqueRôle
Adéquation fonctionnelleFait ce qui est demandé
Efficacité de performanceTemps de réponse, ressources
CompatibilitéCoexiste avec d'autres systèmes
Facilité d'utilisationApprentissage, ergonomie
FiabilitéFonctionne sans défaillance
SécuritéConfidentialité, intégrité
MaintenabilitéCapacité à corriger / améliorer
PortabilitéChangement d'environnement

La maintenabilité couvre la correction (corrective), l'adaptation (adaptative) et l'amélioration (perfective).

Métriques de code

MétriqueDéfinitionSeuils
LOCphyLignes physiques (avec blancs et commentaires)—
LOCproLignes productives (instructions seules)—
V(G) McCabeE − N + 2 ou nombre de décisions + 11–10 simple, 11–20 modéré, >20 complexe

V(G) = nombre minimal de cas de test pour couvrir toutes les décisions.

Exemple du contrôle (WMC/CBO/LCOM)

Classe GestionClient :
  getNom()          → V(G) = 1 (utilise nom)
  ajouterCommande() → V(G) = 1 (utilise commandes)
  totalAchat()      → V(G) = 2 (boucle for sur commandes)
  notifier()        → V(G) = 1 (utilise EmailService + SMS)

WMC   = 1 + 1 + 2 + 1 = 5           → faible (≤10)
CBO   = EmailService + SMS = 2      → faible (≤5)
LCOM  = P − Q = 5 − 1 = 4           → faible cohésion (>1)

Diagnostic d'une classe

ValeurInterprétation
WMC = 28> 20 → trop complexe
CBO = 12> 10 → couplage excessif
LCOM = 5> 1 → faible cohésion

Recommandations : refactoriser pour réduire la complexité, découpler (interfaces, injection), revoir la cohésion (split si nécessaire), renforcer les tests et faire une revue de code.

Apprentissage non-supervisé

Données ni classées, ni étiquetées. L'algorithme découvre la structure seul (clustering, réduction de dimension, détection d'anomalies).

K-means : les 4 étapes

  1. Initialiser k centroïdes aléatoires
  2. Assigner chaque point au centroïde le plus proche (distance euclidienne en général)
  3. Mettre à jour chaque centroïde = moyenne des points du cluster
  4. Répéter jusqu'à convergence (centroïdes stables) ou max d'itérations

Inertie

Inertie = Σ ||xi − centroïde(xi)||². Mesure la compacité : plus faible = mieux.

Avantages / Inconvénients

AvantagesInconvénients
Simple à implémenterSensible aux outliers
Rapide (petits/moyens)Nécessite de fixer k
Bien sur données compactesMinimum local (init.)

Variantes

  • K-medoids : utilise la médiane (ou un point représentatif) au lieu de la moyenne → robuste aux outliers.
  • K-means++ : initialisation intelligente. 1er centre aléatoire, puis chaque nouveau centre tiré avec probabilité ∝ D(x)². Réduit les mauvaises initialisations.
  • Mini-batch K-means : sous-échantillons → rapide sur grands ensembles.
  • DBSCAN : clustering par densité, adapté aux formes complexes.

Méthode du coude (elbow)

  1. Tester K-means pour k = 1, 2, 3…
  2. Calculer l'inertie pour chaque k
  3. Tracer k (x) vs inertie (y)
  4. Le coude = point où l'inertie chute beaucoup moins → k optimal

Applications

Segmentation de marché, compression d'image, analyse de texte (docs similaires), détection d'anomalies.

Types d'agents

  • Réflexe simple : règle condition-action

  • Basé sur des buts : cherche à atteindre un but
  • Basé sur l'utilité : pondère plusieurs critères
  • Apprenant : améliore ses performances par l'expérience

Agent rationnel ≠ omniscient

Rationnel : maximise la performance attendue avec les infos disponibles. Omniscient : connaît l'état réel complet et toutes les conséquences (idéal inatteignable).
