find() : lire les documents

db.collection.find(query, projection, options) — renvoie un curseur vers les documents (pas directement les documents). Sans argument, retourne tous les documents. Joue le rôle de SELECT … WHERE en SQL.

ParamètreRôle
queryFiltre (opérateurs). {} ou omis = tous les documents.
projectionChamps à renvoyer. Omis = tous.
optionsOptions supplémentaires (comportement, format).

Opérateurs de comparaison

OpérateurSignification
$eqÉgal à
$neDifférent de
$gt / $gteSupérieur (ou égal)
$lt / $lteInférieur (ou égal)
$in / $ninAppartient / n'appartient pas à un tableau
db.Films.find({ annee: { $gt: 2010 } })
db.Films.find({ realisateur: { $in: ["Christopher Nolan", "James Cameron"] } })

Combiner des conditions

Plusieurs champs dans le même objet = ET implicite ($and). Pour un OU, utiliser $or.

db.Films.find({ titre: "Inception", annee: 2010 })       // AND
db.Films.find({ $or: [
  { realisateur: "Christopher Nolan" },
  { genre: "Science-fiction" }
] })                                                       // OR

  { annee: { $gt: 2000 } },

Sous-documents : notation pointée

Pour atteindre un champ imbriqué, on utilise la notation pointée entre guillemets :

db.Etudiants.find({ "adresse.ville": "Agadir" })

Attention : { adresse: { ville: "Agadir" } } exige une correspondance exacte du sous-document entier (tous ses champs), pas seulement ville.

Tableaux : trois outils

$ positionnel : première occurrence seulement. $[elem] + arrayFilters : toutes les occurrences qui respectent la condition.

db.produits.updateMany({},
  { $set: { "avis.$[elem].note": 8 } },
  { arrayFilters: [ { "elem.client": "Amal" } ] })

Embedding ou referencing ?

Embedding : lecture rapide, pas de jointure, mais document plus gros (limite 16 Mo) et mises à jour plus lourdes. Referencing : pas de duplication, mises à jour simples, adapté au plusieurs-à-plusieurs, mais plusieurs requêtes ou $lookup.

Pièges classiques

  • Sous-document : toujours la notation pointée ("adresse.ville").
  • Deux conditions sur le même élément d'un tableau : $elemMatch.
  • $pull avec condition retire tous les éléments qui correspondent.
  • replaceOne : aucun opérateur, tous les champs à garder à réécrire, _id conservé.
  • Tri, puis skip, puis limit, quel que soit l'ordre d'écriture.

PHP : structures de contrôle

Un script PHP s'exécute par défaut de façon séquentielle. Les structures de contrôle modifient cet ordre : les instructions conditionnelles exécutent un bloc seulement si une condition est vraie, les boucles répètent un bloc. Tout repose sur des conditions, construites avec des opérateurs.

Comparaison souple vs stricte

== convertit les types avant de comparer ; === exige la même valeur et le même type.

"7" == 7        // true
"7" === 7       // false
null == false   // true
null === false  // false
"1e3" == "1000" // true (piège !)

Règle : utiliser === et !== par défaut, == seulement pour ignorer volontairement le type.

Incrémentation

$i++ (post) renvoie la valeur actuelle puis incrémente ; ++$i (pré) incrémente puis renvoie la nouvelle valeur. Seule sur sa ligne, les deux formes sont équivalentes.

$i = 5;
echo $i++;   // affiche 5, puis $i vaut 6
echo ++$i;   // affiche 7

Valeurs « falsy »

Sont considérées comme fausses : false, 0, 0.0, "", "0", le tableau vide [] et null. Toutes les autres valeurs sont vraies.

Évaluation en court-circuit : dans A && B, si A est faux, B n'est pas évalué ; dans A || B, si A est vrai, B n'est pas évalué.

if / elseif / else

$note = 13.5;
if ($note >= 16) {
  $mention = "Très bien";
} elseif ($note >= 14) {
  $mention = "Bien";
} elseif ($note >= 12) {
  $mention = "Assez bien";
} elseif ($note >= 10) {
  $mention = "Passable";
} else {
  $mention = "Non validé";
}
// mention : "Assez bien"

Les conditions sont testées dans l'ordre : dès qu'une est vraie, son bloc s'exécute et les suivantes sont ignorées. Tester du plus restrictif au plus large. Toujours mettre les accolades.

switch et match

switchmatch (PHP ≥ 8.0)
NatureInstructionExpression (renvoie une valeur)
ComparaisonSouple (==)Stricte (===)
breakObligatoire à chaque caseAucun
Si aucun casRien ne se passe (ou default)Erreur sans default
// switch : deux valeurs regroupées
switch ($jour) {
  case 6:
  case 7:
    $nom = "Week-end";
    break;
  default:
    $nom = "Autre jour";
}

// match : tester des intervalles
$m = match (true) {
  $note >= 16 => "Très bien",
  $note >= 14 => "Bien",
  default     => "Non validé",
};

Sans break, l'exécution « tombe » dans le case suivant : source d'erreurs fréquente.

Ternaire et coalescence nulle

$statut = ($age >= 18) ? "majeur" : "mineur";
$page   = $_GET['page'] ?? 1;   // valeur par défaut

?? renvoie l'opérande de gauche s'il existe et n'est pas null, sinon celui de droite. Les ternaires imbriqués sont interdits sans parenthèses en PHP 8.

Syntaxe alternative dans une vue

<?php if ($connecte): ?>
  <a href="logout.php">Déconnexion</a>
<?php else: ?>
  <a href="login.php">Connexion</a>
<?php endif; ?>

Les accolades sont remplacées par : et fermées par endif;, endfor;, endforeach;, endwhile;. Recommandé dans les vues ; préfigure les directives Blade de Laravel.

Bonnes pratiques

  • Utiliser === par défaut, == seulement pour ignorer volontairement le type.
  • Éviter les conditions imbriquées : combiner avec && / || ou utiliser un retour anticipé (exit / return).
  • Toujours mettre les accolades, même pour une seule instruction.
  • Préférer match à switch quand on associe une valeur à un résultat.
